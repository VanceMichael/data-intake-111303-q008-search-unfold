# 来源与接收约定

GET /search 提供 view 与 groups。每组 members 地址可多页，next 为 null 才闭合；页 view 也须一致。input.maxRefresh 限制视图刷新次数，默认 2。输出 complete、ids、membership 和 unresolved 组 id；保留每次视图的覆盖证据。

## 边界与操作

来源地址由启动函数动态分配，不固定端口。所有时间值只按各自字段的业务含义使用；不以请求抵达顺序推导资料版本。可见结果应附真实原始响应、页面或运行证据，不能仅根据调用参数生成结果。

来源演练用例位于 fixtures/cases.json，name 为当前情形名称，routes 为实际供方响应。工作流只通过 source 暴露的接口或页面访问来源；不得导入模拟源内部状态、读取它的文件来代替真实采集。浏览器门户内部动作接口只服务页面，不是机器人可直接调用的业务 API。

读取失败不等于不存在；部分资料可以保留，但需要完整性承诺的结果不能伪称完成。重启时只能复用已落盘且能追溯依据的进度。输出可扩展更多证据字段，但不能省略下列业务状态。

## 业务输入与结果

### 代表项不代表全组

业务输入：
```json
{}
```
结果必须包含：
```json
{
  "complete": true,
  "ids": [
    "a",
    "b"
  ]
}
```

### 失效视图不能宣称闭合

业务输入：
```json
{
  "maxRefresh": 1
}
```
结果必须包含：
```json
{
  "complete": false,
  "unresolved": [
    "g1"
  ]
}
```

### 交叉成员保留两个组关系

业务输入：
```json
{}
```
结果必须包含：
```json
{
  "complete": true,
  "ids": [
    "a",
    "b",
    "c"
  ],
  "membership": {
    "a": [
      "x",
      "y"
    ]
  }
}
```
